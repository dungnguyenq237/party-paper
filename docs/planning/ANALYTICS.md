# Measurement contract and product decisions

Begin with operational telemetry required to run rooms, and separate voluntary product analytics. Existing print routes currently have no trackers. Obtain a privacy review, revise notices and build an effective off switch before enabling optional events. Apply consent choices including withdrawal. Use backend counters wherever possible and avoid adding a marketing SDK for the pilot.

| Event | Authoritative trigger and allowed values | Decision or denominator |
|---|---|---|
| landing_view, create_intent | Opt-in public page view or Create press · locale, game, public release version, coarse allowlisted referral category | create intents / eligible measured landing views · report consent coverage, traffic class and bots separately. |
| room_created, join_attempt, seat_joined | Committed create · join UI attempt · new persisted seat (refresh excluded). Invite source = code, link, QR or direct. | room-to-start and joined seats / measured attempts by method · same person can attempt more than once. |
| invite_shared, invite_opened | Native share completion signal when available or copied link (distinguish) · generic join shell arrival | joins of invited cohort / observed invite opens · OS share is a proxy for sending. Classify without logging URL/code. |
| match_started, round_completed, match_finished, match_abandoned | State transition committed once, reason enum, seat-count band and duration bucket | completion = finishes / starts from same closed start cohort. Abandonment = abandonments / starts. Show still-active matches separately. |
| seat_left, disconnected, recovered, action_rejected | Leave/timeout, lost transport, successful seat resume, bounded reason/error type | drop share by phase, resume fraction, p50/p95 ack and reconnect latency. No raw action payloads or network addresses in product data. |
| rematch_started, results_shared | Committed new match referencing a just-finished match in temporary aggregation, explicit share action | finished rooms starting a rematch / eligible finished rooms · share actions / consenting result views. |
| returning_host, cohort_return | Optional device-scoped random identifier with informed opt-in, first host date and return buckets D1/D7/D28 | Retention = opted-in original host cohort returning in window / eligible original cohort. No cross-device merge or fingerprint. With insufficient consent, report repeat pilots and in-room rematch only. |
| purchase_settled, purchase_refunded, usage_charged | Validated order transition (future), SKU class/game, amount/currency, metered units | Net contribution = settled − refunds − fees − service costs − directly attributable production/support. Report per completed session and per paying host. |

Every event has schemaVersion, date bucket, gameId, engine/content version and platform release. Deduplicate transactional counters by business key (e.g. matchId + transition), then discard the transient identifiers with the room. Observer-selected locale and device class are coarse. Omit them where tiny cells could identify participants. Never collect audio, prompt content, votes, answer text, private objectives, room codes, full URLs/referrers, names or payment details. Diagnostic logs use a short-lived random trace ID, error code, latency, component and region. Retain up to 7 days. Optional raw product events expire within 14 days, optional return identifier expires after 30 days of inactivity and daily aggregates roll off after 13 months. Erase opt-in linkable rows on withdrawal and suppress small published cohorts (initially <10 rooms). Do not promise control over provider access logs before verifying retention. Maintain a schema allowlist test and an analytics-disabled E2E run.

## Use the data to decide

Baseline the first hosted trials by language, size, invite source and game. Pre-register a hypothesis, experiment dates, minimum observation window and cost of a wrong decision. For a convenience pilot of 20 independent groups, 15 completions implies 75% observed but a rough Wilson 95% interval of 53–89%. Treat it as usability discovery, not a release-wide conversion rate. Avoid counting 100 guests at one wedding as 100 independent hosts. Track both elapsed match duration and active minutes by phase. Compare cohorts with equal opportunity to finish.

If rooms fail before start, inspect slot requirements, join failures and host instruction recordings/notes collected with permission. If they start and leave at the same phase, simplify that action and retest the same locale and size. Fund a second content pack only when observed paid intent and margin plausibly cover its authoring and support, using [unit economics](MONETIZATION.md). If two material iterations fail to improve the diagnosed behavior and opportunity cost is higher than alternatives, pause that game. Invest in an independent product only when audience acquisition, repeated host bookings, positive contribution and the operational need for separate deployment all persist. Feature flags let the rest of the collection continue. Unavailable Search Console, ad and cohort data must remain labeled unknown.

## Independent review: decision units (IR-H07, IR-M02)

Record P0/L1 evidence per independent host/group, not per guest. Capture first action time, teach-back failures, idle/pass/abstain fraction, unaided completion, rematch and actual committed second session separately. Use roadmap thresholds as proposed directional gates, not statistically proven demand; record denominator, language/size, selection and consent bias, intervals, observed support and cost. Do not silently extrapolate opt-in traffic to all visitors. Operational telemetry is distinct from voluntary product analytics; no third-party tracker in rooms. Suppress tiny cohorts and expire linkable data. No revenue forecasts without actual paid-intent and cost evidence.
