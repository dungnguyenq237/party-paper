# Architecture and product decision log

**Every decision is proposed and awaits owner review.** Source of truth for the choice and reconsideration trigger. The linked specification defines mechanics. Record any change here with date, owner, superseded ID and evidence.

| ID · choice | Context and alternatives considered | Rationale, trade-off and consequence | Evidence required to confirm or revisit |
|---|---|---|---|
| D01 · Party Partner is a live collection within Party Paper | Existing site/metadata say Party Paper. The owner could rename everything or register separate brands immediately. | Preserve existing URLs, audience and print workflows · one public origin and catalog. Two names require clear navigation. | Owner confirms naming and canonical domain rights · test if first-time hosts find print and live separately. |
| D02 · One TypeScript modular monolith with native static pages | Existing ES modules have no client framework. Other options include rewriting in Next.js, copying eight apps or adopting a universal board-game engine. | Reuse local print frontend. Strict new contracts/isolated engines satisfy very different games · custom server/UI code needs maintenance. | Two nontrivial engines fit contract and bundles exclude unrelated/private code. |
| D03 · One Node writer and durable SQLite at pilot | No current backend or DB evidenced · Render origin already public. Compared managed Postgres, Cloudflare Durable Objects and serverless polling. | Lowest number of moving parts and easy local replay · single region, bounded throughput, attached-volume restart downtime. A room actor platform could become cheaper at burst scale but changes host/domain/tooling. | Verify actual host/plan/origin, measured ack/fan-out, volume restore and hosting cost. Reconsider actor hosting or database when SLO/cap blocks a paying cohort. [Render](https://render.com/docs/disks) · [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/) |
| D04 · Server owns private state, receipts and deadlines | Browser print code legitimately includes all answers. Compared client host authority, public snapshots with client filtering and a full permanent event log. | Per-viewer allowlists, committed snapshots and deduplicated receipts survive refresh/host loss. Smaller privacy footprint than full permanent replay. More test fixtures required. | Projection/asset scan and crash-after-commit tests · prove restore across prior content versions. |
| D05 · Friend Court first, flagship tested second | Wedding maximizes commercial potential but needs event operations. Corporate needs careful balancing. A trivial poll would miss voting and private turns. | One short game proves invite, deadline, committed private choice, rematch and accessible performance. Friend Court alone cannot prove economic transactions or large fan-out. | Unaided mixed-language host sessions, then Corporate and one contention fixture before freezing broader helpers. |
| D06 · New bilingual static routes and keyed UI | Existing print scanner and 38 catalogs serve legacy routes. Other options include cloning 38 SEO pages per game or depending on client-side translation. | EN/VI editorial investment buys understandable rules and crawlability. Linguistic maintenance per new pack grows. | Native review of both variants, matching stable answer IDs, static crawl and coverage checks. |
| D07 · Wedding cap set by rehearsal and workload | Revenue timing and audience burst differ from small rooms. Alternatives include launching 300 by configuration or operating separate event SaaS immediately. | Single platform with narrower operator grants, venue fallback and explicit tested cap. Early bookings need hands-on support. | Actual venue, co-host recovery, reconnect storm, paid pilot contribution · re-evaluate separate platform when booking SLA demands it. |
| D08 · Audio stays private and disposable | Compared automatic public reveal links, permanent archive and live voice calling. | Consent, short private recordings, timed deletion and a complete text relay minimize infrastructure and group exclusion. Ephemeral storage can lose a hop on restart. | Cross-device codec and deletion tests on actual chosen storage, abuse/report staffing and consent feedback. |
| D09 · Published replay corpus first for AI | Compared continuous inference, BYOK and purely human mock judging. | Genuine pre-generated outputs make deterministic multiplayer practical with zero recurring inference. A finite corpus can be learned and is expensive to refresh. | Corpus rights, replay willingness, benchmark editor cost. Allow live mode only with token caps, verified unit margin and an owner-approved ceiling. |
| D10 · Hold billing/ads until a buyer and operating owner exist | Existing ad adapter inactive. Alternatives include displaying ads in every game or requiring account subscriptions. | Sell a reusable host unlock/event only after evidence. Protects group conversion and privacy, delays revenue. | Measured paid pilots, reviewed terms, consent/AdSense approval if applicable and webhook/refund/restore proof. |
