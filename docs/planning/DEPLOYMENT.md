## Monthly cost sensitivity

Assume workspace base $0 in the example, an available 5 GB monthly outbound allowance, $0.15/GB beyond it, $0.25/GB-month disk. Starter compute $7, 1 CPU/2 GB $25, 2 CPU/4 GB $85. Recheck eligible workspace tier, taxes, domain, backup storage, monitoring, payment fees and actual included bandwidth before purchase. Approximate **incremental plan cost** = compute + disk + max(0, estimated outbound − available allowance) × unit rate + optional services. If existing usage consumes the allowance, the marginal cost increases. [Render pricing](https://render.com/pricing)

| Scenario/month | Workload assumptions | Compute + disk + egress | USD per month / per completion |
|---|---|---|---|
| Private pilot | 300 starts, 240 completes, 10 peak rooms × 6, 2 GB outbound | 7 + 1 GB × .25 + 0 | $7.25 / $0.0302 |
| Returning groups | 5,000 starts, 4,000 completes, 50 peak rooms × 6, 25 GB outbound | 25 + 5 GB × .25 + 20 × .15 | $29.25 / $0.0073 |
| Event stress envelope | 20,000 starts, 16,000 completes, 4 simultaneous 300-guest events plus 100 ordinary rooms × 6, 120 GB outbound | 85 + 10 GB × .25 + 115 × .15 | $104.75 / $0.0065 |

Egress inputs include static and live traffic. Estimate usage from traces by adding page visits × transferred assets, per-viewer snapshot bytes × sends and media bytes × authorized plays. Stress envelope is a load target, never a sales commitment. Staging at production size can double fixed compute. Hosting is usually a small expense beside translations, moderation, editorial work, refunds and event-day support. Model contribution per game in [monetization](MONETIZATION.md).

**Voice.** Eight seats × four 8 s clips × 32 kbit/s ≈ 1.024 MB recorded per match before overhead. At four plays per clip, 1,000 sessions add about 4.1 GB outbound. At 8 seats the hard cap is 8 MiB; at the 12-seat maximum, 48 × 256 KiB = 12 MiB/match (1.536 MB at example encoding rate). Reserve worst-case space, partial uploads and deletion time separately. Separate temporary media from snapshotted durable data. To establish deletion behavior and price, pilot a quota-limited ephemeral non-backed-up media directory with restart-to-gap UX. Private object storage with lifecycle expiry becomes justified if reliable replay across restarts or larger events is required. Record its storage/request/egress bill separately.

**AI.** Replay mode has $0 live inference cost. Editorial preparation costs occur before release. Record source/rights, usage and editor hours per pack. For optional live text use a *budgeting example*, $0.50/M input and $2/M output tokens, not a provider quote. A six-seat three-round match with one call per seat/round, max 600 total input and 150 output tokens/call costs at most 18 × (600×.50 + 150×2)/1M = $0.0108 before moderation/failed calls. At 80% completion that's $0.0135 per completed match. At eight seats it is $0.0144 per started match. 10k six-seat starts consume $108 before extras. Count retries in the same reservation, cap provider tokens (including billable reasoning if supported) and disable paid mode when reserve is insufficient. Hypothetical $30 monthly author-approved cap permits at most 2,777 such starts at the example rate before overhead. Default live allowance is zero. Pin an actual supported model, token semantics and current price before any purchase. Configure per-event, per-day and per-month ceilings and compare vendor bill to ledger. ## Operator procedure and scale decision

1. Repository owner verifies hosting, region, domain and bill and declares maximum recurring spend. Measure mobile RTT from Vietnam and an international cohort to candidate regions. Choose one region for the pilot. Make build require an allowlisted PUBLIC_ORIGIN, production secret(s), disk path, protocol compatibility range and feature flags. Use fake keys only in a separate test environment.
2. In staging produce both a public HTML/JS/assets directory and a private server bundle. Validate root and Pages-prefix static paths, fresh node boot, read-only /health and readiness with DB migration checks. Bind Render's PORT on 0.0.0.0. Ensure proxies handle upgrades, session cookies and no-store room responses. Probe old pages after the staging build. Review permissions, disk mount and retention for every environment.
3. Before deploy, freeze new room creation and schedule a drain outside booked events. Notify existing clients, finish live rooms or snapshot for version-compatible resume. On SIGTERM reject new writes, finish in-flight commits, close sockets with retry signal and exit. Attached disks restrict horizontal scaling and zero-downtime deploy. Disable production auto-deploy before hosting. Run additive migrations at runtime (attached disk unavailable at build/pre-deploy), single owner, schema version, prior reader until room expiry. [Disk constraints](https://render.com/docs/disks)
4. On restart check DB integrity, scan deadlines, delete expired records before serving reads, then permit joins. For crashes on intact disk target zero acknowledged-action loss and reconnect within 30 s after readiness. On lost/rolled-back disk abandon all transient matches; discard sessions, receipts, invites and media grants, rotate guest-session namespace/key before traffic. Never restore transient rooms or rely on markers from an older backup. Backup persistent commercial entitlements separately when introduced. Proposed entitlement RPO 24 h and RTO 2 h, reconcile recent payments with provider receipts to avoid permanent purchase loss. Test an isolated restore before selling.
5. Track p95 commit-to-ack, event-loop delay, SQLite busy/lock duration, disk/WAL growth, bytes per recipient, memory, join/reconnect failures, cleanup age and cost/completion. Alert on sustained user-visible deadline misses, cleanup drift or budget-cap approach. Record runbook and on-call owner. Cap new rooms, coalesce display frames and turn off optional media first. Existing leases keep precedence.
6. Vertical scaling first if measurements show CPU/memory saturation. If booking requirements demand failover or single-writer contention remains after bounded snapshots, benchmark managed PostgreSQL with transactional row locks and room ownership/fencing. Route each room to a single current owner and resume from durable state. Add routing/pubsub only after a two-instance reconnect/failover test demonstrates need. Do not attach the SQLite volume to two writers. One 300-seat pass does not establish four-event capacity.
7. Roll back by disabling new rooms for the affected game, draining pinned matches, routing public traffic to the verified static artifact and reverting the app to the previous reader-compatible build. Never downgrade a live schema destructively. Restore durable commercial records only (when introduced) in isolation, reconcile provider receipts and apply retention before cutover. Use SQLite-consistent backup API or VACUUM INTO, not raw live-file/disk copies; Render cautions against custom DB disk snapshot restoration. Document provider daily snapshots/7-day retention separately from logical deletion. Never restore transient room/session/audio. [SQLite backup API](https://sqlite.org/backup.html)

## Independent review: load and rollback (IR-C01, IR-H03, IR-H06)

Scenario prices are arithmetic, not capacity/invoice evidence. Outbound = encoded snapshot bytes × recipients × sends. Six seats × 4 KiB × 80 sends per seat ≈ 1.97 MB/match, 9.83 GB/5,000 starts before assets/retries. Naive 300 seats × 300 answers × 2 KiB ≈ 184 MB/round. Private ACK + coalesced interested-view updates; no full fan-out per answer. 2 Hz projector cap never delays private ACK. Load test actual bytes, queue age, CPU/RSS, fsync, RTT, cleanup; choose caps accordingly. P0 verifies actual service ID/type, branch, commands, tier, disk, region, bill/allowance, domain rights, budget. No purchase authorized. Pages mirror is not automatically same-URL failover. Test failed build, incompatible migration refusal, intact restart, lost-disk abandonment and verified static rollback in staging. No zero-downtime/capacity promise.
